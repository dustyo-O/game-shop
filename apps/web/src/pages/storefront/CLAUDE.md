# `pages/storefront`

The shop's front page at `/`: the mockup's upper half — header, banner, service tiles, Steam top-up, one product row — as page-local sections with every Russian string in `config/`; the five graded interactions live here, and the row hands «Купить» to `features/buy-product`.

- **One `document` click listener for the catalog menu, none on the Каталог button** — `ui/catalog-menu.ts` registers it, and it classifies every click on the page exactly once (on the button / inside the overlay / outside) and hands that class to `reduceMenu` in `model/menu.ts`; the reducer decides, the binding paints `hidden` and `aria-expanded`. A second `document` click listener for the menu, or one on the button, reintroduces the bubbling-order bug R3 describes — the opening click bubbling up to be read again as an outside click — and the usual patch, `stopPropagation`, is untargeted — it hides events from whoever is above, which on this page means `enableBuyControls`'s delegated listener on the product row and this very `document` listener, which needs the «Купить» click to reach it. Checks: `grep -n 'addEventListener("click"' ui/catalog-menu.ts` returns one line, on `document`; `grep -rn '\.stopPropagation(\|\.preventDefault(' --include='*.ts'` over this directory returns nothing. "Inner clicks are inert" is markup, not a handler: categories are `<button type="button">` with no listener, items are `<li>` text, and `grep -rn 'createElement("a"' --include='*.ts'` over this directory returns nothing (Slice 3).
- **One timer slot for the carousel, and one `setTimeout` on the page** — the call is in `model/countdown.ts` and nowhere else (`grep -rn "setTimeout(" --include='*.ts'` over this directory returns that one line). `model/carousel.ts` emits exactly one timer instruction per event (`restart` / `cancel` / `keep`); `ui/banner.ts` turns it into a call in one function, `applyTimer`; and `restart` always clears before it sets, so there is never more than one pending timeout. Anything that later wants a timer here — a second carousel, a delayed hover, a toast — routes through that reducer and that countdown rather than calling `setTimeout` itself. `pagehide` cancels the countdown; a persisted `pageshow` restarts it through the reducer (Slice 2).
- **No script touches the currency group** — the «$ / ₸ / ₽» control is three native `<input type="radio" name="currency">` in a `<fieldset role="radiogroup">` (`ui/steam-topup.ts`), and the radio group *is* the state: the browser keeps exactly one checked, moves it with the arrow keys, and `storefront.css` paints `:checked + label` and `:focus-visible + label`. There is no handler, no `aria-pressed`, no class toggled, and nothing to recalculate (the ₽/$ mismatch in the block is the mockup's and stays). Checks: `grep -rn 'name: "currency"' ui/*.ts` returns one line, in `steam-topup.ts`; `grep -n addEventListener ui/steam-topup.ts` returns nothing. Anyone tempted to add a `change` listener there should first read the comment on `renderCurrencyOption` — a handler whose whole logic is "set this one true, the others false" reimplements what the group already does (Slice 4).
- **Hover is CSS, in three durations, with no outline reset** — every hover state is a `transition` in `ui/storefront.css` (tiles 160 ms, cards 180 ms, everything else 120 ms), `:focus-visible` shares each `:hover` rule except the currency label's (its keyboard state is the `:focus-visible + label` ring) and the card uses `:focus-within` for Купить, and `@media (prefers-reduced-motion: reduce)` withdraws only the card's `transform`. No script and no class is involved in hover, so a hover assertion reads computed style after the duration — never mid-fade (R14). Check: `grep -n "outline: none\|outline:none\|outline: 0" ui/storefront.css` returns nothing (Slice 4).
