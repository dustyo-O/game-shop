# Tasks: Storefront per the Design

- **Spec:** `004-storefront-per-the-design`
- **Functional:** `functional-spec.md` — 10 requirements, 44 acceptance criteria
- **Technical:** `technical-considerations.md` — 5 sections, 20 risks, 12 assumptions

> **Standing requirement.** Every slice ends with a task explaining to the user how that feature works and its role among the key points of the test task. This is a deliverable, not a courtesy: the assignment grades «способность объяснить решения». For this phase the question a reviewer will actually ask is *why these five interactions and not the rest* — every explain task must be able to answer it.
>
> **Four things every slice must honour**, all from the tech spec:
> - **R4 — CSS is scoped by selector, not by file.** `storefront.css` is in every route's bundle. No `body`, `html`, `*` or bare element rules; every selector starts with a storefront-owned block. Re-screenshot `/order/:id` and `/admin/recovery` whenever the sheet changes.
> - **R13 — the e2e restores the API suites' baseline.** `apps/api` asserts `orders = 0` and `unclaimed = 50` before it runs. Any order the browser tests create is deleted in `afterEach` through the same six statements as `cleanupTestOrders`; ids are captured from the `POST` response, never the URL. `pnpm test` must be green after `pnpm test:e2e`.
> - **RED weakens nothing in `src/`.** Write-first for new behaviour; for every "nothing happened" assertion, run the identical assertion against Купить and watch it fail; for every "state changed" assertion, push the clock past the boundary or assert the pre-state. Quote the failing line in the walkthrough.
> - **Ports are 5101 (Vite) and 5102 (API), `--strictPort`.** Three phases, three near-collisions. Both go into `scripts/race/README.md`'s port row in Slice 1 and nothing else may bind them.
