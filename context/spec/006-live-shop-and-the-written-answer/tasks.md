> **Standing requirement.** Every slice ends with a task explaining to the user how that feature works and its role among the key points of the test task. This is a deliverable, not a courtesy: the assignment grades «способность объяснить решения». Phase 6's sentence to be able to say unaided: *passing the race checks on Vercel, where every request is its own process, is evidence that the guarantees live in Postgres and not in memory.*
>
> **Rules every slice honours**, all from the tech spec:
> - **Nothing about the shop's behaviour changes.** A behaviour found wrong during deployment is a bug against its own spec, fixed there — not here. `pnpm test`, `pnpm test:e2e` and `pnpm race` stay green locally after every task that touches code (R13's order; foreground runs; one database user at a time; load below ~14 — see memory).
> - **User steps are marked `(User step first)`.** They need an account or a dashboard: `vercel login`/`link`, the Fluid Compute toggle, the Neon project, `gh auth login`. The orchestrator asks the user to run them with `! <command>` before delegating the task; the agent does everything after.
> - **No secret ever enters the tree.** Neon URLs and CLI tokens live in the shell for the session; `.env` is gitignored; the one published token is the demo `ADMIN_TOKEN`, generated fresh and labelled. `git diff` is read before every commit.
> - **Deploy only from a clean, committed tree** — `vercel --prod` uploads the working tree, and the live shop must equal the published sources.
> - **Ports** 5401 (`vercel-entry.test.ts`) and 5402 (`demo-routes.test.ts`), listed in `scripts/race/README.md`'s row; nothing else may bind them.
