# Tasks: Promo Codes with Enforced Limits

- **Spec:** `005-promo-codes-with-enforced-limits`
- **Functional:** `functional-spec.md` — 7 requirements, 31 acceptance criteria
- **Technical:** `technical-considerations.md` — 5 sections, 15 risks, 10 assumptions

> **Standing requirement.** Every slice ends with a task explaining to the user how that feature works and its role among the key points of the test task. This is a deliverable, not a courtesy: the assignment grades «способность объяснить решения». The roadmap names this phase's concept outright: *why a read-then-increment is a race, and how a single conditional update replaces it* — every explain task must be able to say it in two sentences.
>
> **Four things every slice must honour**, all from the tech spec:
> - **R1/R2 — the race is invisible in one process, and the CHECK masks a broken guard.** A `max: 1` pool serialises inside one instance (architecture §7: 20 distinct keys against 1 process, 9 against 4), so the limit is proven across four API processes only. And a weakened guard's fourth increment trips `CHECK (used_count <= max_uses)` as a `500` with `used_count = 3` — a counter-only assertion stays green. Every proof asserts the *shape* of the refusals (exactly N × 200, the rest × 409 exhausted, **zero 5xx**) and the ledger rows, not the counter alone.
> - **Refusals before writes.** The transaction (tech spec §2.2) decides every refusal — lock, status, existing redemption, code lookup, the I7 increment — before either write; an expected refusal commits empty. No sentinel throws. The view is read **after** COMMIT (a `max: 1` pool self-deadlocks on a pooled read inside the transaction).
> - **R13 — both harness files move together.** `apps/api/test/concurrency/support/db.ts` and `apps/web/e2e/support/db.ts` gain the same baseline rows and the same cleanup CTE (delete this test's redemptions, decrement by exactly that — never a global recompute). `pnpm test` must be green after `pnpm test:e2e` and after `pnpm race promo`.
> - **Ports** are 5201–5204 (the race test) and 5301 (acceptance), listed in `scripts/race/README.md`'s row; nothing else may bind them.
